# 五角色单股票评测集（20 条）

状态：**题目与评分规则待验收；数据证据待采集；未运行、未评分**。用例见 [`five_agent_20.jsonl`](five_agent_20.jsonl)。这套数据只评估当前的 Fundamental、News、Market、Investment、Risk 五角色研究链路，不改变运行时研究或 Verify 逻辑。

## 输入边界

当前研究入口 `UnifiedAnalysisRequest` 只接收 `target` 和 `as_of`。因此每条用例的 `target` 是实际提交值，`grading_focus`、`role_checks` 和 `failure_traps` 是**评测者的检查依据**，不会作为额外问题或提示词发送给 Agent。每次运行只分析一只股票；20 条用例的 `target` 两两不同，均选自现有 `samples.json`。`reference_name` 与 `selection_group` 仅用于选样和阅读，提交时以交易所限定的 `target` 为准，运行前须核对名称的时点有效性。

`as_of` 目前为 `null`，表示尚未冻结研究时点；**正式评测不得直接按 null 提交**，否则 API 会使用运行当时的时间，不同批次无法严格比较。后续完成 DataOps 时，先给每条用例写入带时区的固定 `as_of`，再保存九个工具的实际输出与版本。新闻角色的查询窗口是近 7 个自然日、每工具最多 10 条；市场角色使用最近 60 根日线和最近 30 个完整交易日的指标。历史窗口能否重建取决于真实数据源，不能凭评测题目假定已有新闻或指标。

## 数据字段

| 字段 | 含义 |
| --- | --- |
| `id` | 用例标识 `FA001`–`FA020` |
| `target`、`sample_id`、`reference_name`、`selection_group` | 单只股票的提交值与选样元数据 |
| `as_of` | 未来冻结的研究时点；目前为 `null` |
| `grading_focus` | 该股票的主要评分关注点，不是给 Agent 的指令 |
| `role_checks` | 五角色分别需要在产物中体现的核对点；数据缺失时检查是否如实披露 |
| `failure_traps` | 容易出现的无依据陈述或口径错误；只有实际发生才记错，不预设公司事实 |
| `reference` | 真实数据锚点；目前统一为 `pending_dataops`，无快照、事实或 Evidence ID |

数据采集后，将 `reference` 扩为经复核的清单：`snapshot_id` 或不可变文件哈希、工具名与调用状态、证券代码、数据版本、`as_of`/`available_at`、财报期间、单位、覆盖状态、关键事实、Evidence ID、标注者与复核者。状态应区分 `available`、`no_data`、`source_error`、`not_disclosed` 和 `not_collected`。空结果不是零，来源失败也不等于公司没有事件。主观推断只评估推理是否有边界、是否与已知证据冲突，不要求它等同于数据库事实。

## 核心评分口径

每条用例满分 100。每个维度先按下表打 `0`、`0.5` 或 `1`，再乘权重；保留逐项原因与证据定位，不只保存总分。若某项因数据源完全缺失而无法评分，记 `not_scored` 和原因，不把它算成通过或失败；同时披露实际计分权重，禁止把剩余分数无说明地归一到 100。

| 指标 | 权重 | 满分条件 |
| --- | ---: | --- |
| 任务完成 | 25 | 完成单股票综合研究；结论、依据、成立条件、反证和限制与该用例关注点相符 |
| 关键事实与数值 | 25 | 影响结论的证券、期间、单位、口径、数值与冻结工具结果一致；派生值可重算 |
| 证据支持 | 15 | 影响结论的事实能回到本次工具结果；引用真实且定位正确 |
| 时点正确 | 10 | 只使用 `as_of` 时已可获得的材料，不引用未来披露或事后修订 |
| 五角色传递 | 10 | Investment 正确使用前三角色的关键材料；Risk 能看到并处理上游缺口 |
| 风险与不确定性 | 15 | 重要风险、来源失败与数据缺口得到明确处理；结论强度与证据覆盖匹配 |

`1` 表示该维度的适用检查点均满足，`0.5` 表示部分满足且无严重误导，`0` 表示未满足或存在影响结论的错误。具体争议需保存裁判说明；开放式分析建议由两名评测者盲评，分歧再复核。数值、期间、单位、Evidence ID、未来信息优先用确定性程序核对；分析完整性和风险表述用固定 rubric 人工评审或经校准的模型裁判。不能让模型裁判自行创造标准事实。

**严重错误门禁**：伪造 Evidence ID、影响结论的重大数值或单位错误、引用研究时点之后的信息、Risk 未完成却呈现“风险低”，均将 `case_pass` 记为 `false`，同时保留六维分数和原因码。单项工具返回 `no_data`、未披露或来源失败时，若报告正确说明缺口，不自动判失败。

## Agent 常用诊断与对照指标

除核心质量分，还记录：九个工具的调用与状态、错误恢复或降级、关键步骤轨迹、任务成功率、重复运行稳定性、总时延、各角色时延、Token 与估算成本。工具调用正确不等于报告事实正确；同一工具的返回为空或失败时，重点评估是否正确处理。若与单 Agent 对照，两者须使用同一批用例、相同 `as_of` 与可比的数据版本，盲评质量并同时报告时延和成本。当前入口没有工具快照回放能力；若两次运行读到不同版本，应标为不可严格配对。

这些维度与 [OpenAI Agent evals](https://developers.openai.com/api/docs/guides/agent-evals) 的任务和轨迹评估、[OpenAI trace grading](https://developers.openai.com/api/docs/guides/trace-grading) 的步骤级定位，以及 [LangSmith evaluation types](https://docs.langchain.com/langsmith/evaluation-types) 的程序评分和模型裁判相符。重复试验可另报 `pass^k`，用于衡量同一用例连续多次均成功的稳定性；该指标来自 [τ-bench](https://arxiv.org/abs/2406.12045)。本数据集尚无任何运行次数，不能填写这些指标的结果。

## 启用真实评测的顺序

1. 完成 20 只股票的 DataOps 后，逐只核对证券主表和名称，冻结每条用例的 `as_of`。
2. 按当前五角色路径取得九个工具的真实响应；保存调用状态、Evidence、数据版本和原始快照哈希。实际空结果和失败分别登记。
3. 从已保存响应标注关键事实、容差、适用风险和不可评分项；完成独立复核后将 `reference.status` 改为 `reviewed`。
4. 运行五角色并保存请求、任务 ID、五角色产物、最终报告及可用轨迹；按固定 rubric 打分。`pending_dataops` 用例只做结构检查，不纳入质量分母。
5. 如需单 Agent 对照或 `pass^k`，另做配对和重复运行；不得把未执行项写成已通过。

这 20 条是一套**可补证据的评测用例**，不是已带标准答案的评测结果。现阶段不能据此计算准确率、任务成功率或宣称五角色优于单 Agent。
